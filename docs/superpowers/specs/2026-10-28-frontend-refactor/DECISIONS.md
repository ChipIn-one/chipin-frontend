## Decisions (final)
D1. Critical fixes go in a separate hotfix PR BEFORE the refactor: invite path traversal (encode segments, validate token format, confirmation screen before join), invite token Sentry leak, money rounding dedupe (use existing roundHalfUp), zero-balance sign bug, PublicLocaleRoute stuck spinner. OAuth PKCE/state = backend issue.
D2. Offline PWA is required: read cached data offline + create/edit/delete expenses offline via an outbox queue replayed in order on reconnect. Phase 1: expenses CRUD. Phase 2: groups/members. Settle-up/payments NEVER offline. Dexie removed; persistence = IndexedDB via TanStack Query persister (idb-keyval or similar).
D3. Server state = TanStack Query (persistQueryClient, networkMode offlineFirst, paused mutations, resumePausedMutations). Zustand stays only for UI state (modals, drafts, ui prefs). Migrate store by store.
D4. API types generated from backend OpenAPI (openapi-typescript + openapi-fetch or thin typed wrapper over axios — writer decides, justify). Contract check in CI. zod only at boundaries where data can be stale-format (IndexedDB cache, outbox, localStorage).
D5. Conflicts: optimistic locking — entities carry `version` (or updatedAt), client sends seen version, server returns 409 with current; client shows conflict UI (keep mine / take theirs). Create: client-generated UUID, idempotent. Delete of already-deleted = success. → backend issues required.
  Superseded by D28 (2026-11-10): no conflict dialog and no "keep mine / take theirs"; versions, 409 with `current`, client UUIDs and idempotent delete stay.
D6. App routing: React Router 7 data router (route objects, loaders prefetching TanStack queries, actions optional, per-route errorElement, one route manifest from which vercel.json rewrites + SW allowlist are generated and tested).
  Amended by D31 (2026-11-10): no loaders that prefetch queries (04-2e withdrawn); per-route `errorElement` and the auth guards stay; `vercel.json` is not generated from the manifest (hand-written, host-scoped catch-all rewrite on the app hosts + a test that every router path is covered by the SW navigation allowlist, 04-2b); route UUID validation is `validateUuidParam` (04-2a3).

## Added 2026-11-05 (owner)

(The `index.ts` depth check of `check-file-layout.mjs` is a different check: where an `index.ts` may exist, not how it is imported.)

## Added 2026-11-10 (owner review of the plan, R1–R6)
R1 (monorepo stays, the site lives in this repo) and R3 (the cache stays on the device when the session expires; accepted risk) keep the current spec text.
D28 (R2, supersedes D5). 409 conflict = a short message ("this expense was changed by another member"); the fresh version from the 409 body (`current`) goes into the cache; the user's changed fields stay as a draft the user can reopen and resend. No compare dialog, no "Keep mine / Take from server". Delete conflict: message + fresh version, the delete is dropped. (03-16b.)
D29 (R4). Tab coordination only through `navigator.locks`: any tab appends ops to the shared IDB queue under a short write lock; draining runs under a separate drain lock held by whichever tab gets it; other tabs get a BroadcastChannel "queue changed" ping and re-read state. No leader election, no epoch fencing, no heartbeat/steal, no IDB inbox. Exactly-once delivery stays on `X-Client-Op-Id` (BE-03-1) + the client id (BE-03-2). A failed op blocks only later ops with the same `entryId`; ops of other entries keep draining. (03-15c.)
D30 (R5, amends D26). The cutover runs in two steps. Step 1 (04-4a1 SW host gate + host-aware kill-switch in the shared build; 04-4a2 app host move): the app moves to `app.chipin.one`/`app-dev.chipin.one` on the current Vercel project before the Astro site exists; `chipin.one` keeps serving today's landing; private app paths on the old hosts 302 to the app host. Step 2 (04-4b, the former 04-4): the Astro site takes `chipin.one`. 03-17 depends on step 1 in prod, not on the site. Rolling back step 2 keeps the step-1 redirects in the app project; rolling back step 1 is a targeted PR that deletes only the legacy redirects. BE-04-2 is on dev and prod before 04-4a2 is merged; on the old hosts the landing sign-in CTAs go to the app host. The step-1 redirects stay 302 and are deleted by 04-5a (with `sw-kill.js` and the `/sw.js` host rewrites); only the site's step-2 redirects become 301.
D31 (R6, plan cuts). (1) Codemods 02-D2/02-D3 withdrawn: named exports via `import-x/no-default-export` with ESLint suppressions that only shrink (02-C13). (2) `packages/tokens` stays but holds a hand-written `tokens.css`, favicon/logo and the theme script; no DTCG `tokens.json`, no generator, no generated `manifest-colors.json`, no `tokens:check`. (3) 05-4 (themeColor codemod) is not a separate PR; the migration folds into the design phase (DS v1 tasks). (4) 04-2e (route loaders) withdrawn; `errorElement` and the auth guards stay.
