# UI Rules

## Design system

Before any UI task read [docs/design-system/README.md](../../design-system/README.md), then only the
files its "If you do X, read Y" list names for your task. Design patterns (hierarchy, money, groups,
states, forms), tokens, the component registry and the component change process
([process.md](../../design-system/process.md)) live there; this file keeps engineering rules and
prohibitions and links to the design system instead of repeating it. When a UI task may start: [AGENTS.md rule 21](../../../AGENTS.md#applies-now) (design-first).

## Radix First

- Prefer Radix Themes primitives, component props, responsive props, and color props.
- Use `Flex`, `Grid`, `Box`, `Container`, `Card`, `Text`, and related primitives instead of rebuilding their basic layout in CSS.
- When Radix props cannot express the requirement, use a CSS Module (`Component.module.css`).
- Do not add another UI or styling library.

## Colors And Styles

- Colors, styled-components and `themeColor()`: follow
  [tokens.md](../../design-system/tokens.md) (§What is forbidden lists each ban with its check;
  styled-components is frozen and `themeColor()` is being removed).

## Inline Styling

- Use Radix props or a CSS Module instead of inline `style`; what `style` may still carry is in
  [tokens.md §What is forbidden](../../design-system/tokens.md#what-is-forbidden).

## Accessibility And Semantics

- Use native elements and Radix semantics before adding ARIA manually.
- Interactive behavior uses `button`, `a`, form controls, or the appropriate Radix primitive; do not make clickable `div`/`span` elements.
- Icon-only controls have translated accessible names.
- Inputs have associated labels and validation messages.
- Dialogs have a title and description; destructive confirmation uses `AlertDialog`.
- Preserve keyboard access, visible focus, and logical focus return.
- Lint (`jsx-a11y`): `alt-text`, `anchor-is-valid` (a link has a real `href`; an action is a `button`),
  `aria-props`, `aria-role`, `role-has-required-aria-props`, `no-static-element-interactions` (no `onClick`
  on a `div`/`span`).

## Images

- Render images in new and touched UI code through `basics/Image`; do not use a native `img` or
  `styled.img` directly.
- Apply specialized presentation with a CSS Module class on `Image`. If the shared component cannot support a required
  image behavior, extend its reusable contract instead of bypassing it in a feature component.
- Keep meaningful alternative text translated. Decorative images use an empty `alt` value.

## i18n And Money UI

- All user-facing strings, placeholders, ARIA labels, toasts, and validation messages use i18n keys.
- Lint: JSX text is `{t('key')}` (`react/jsx-no-literals`), and `aria-label`, `aria-description`,
  `placeholder`, `title`, `alt` take `{t('key')}`, not a string literal (`[i18n-attributes]`). Technical
  attributes (`variant`, `size`, `type`) are not checked; test files are excluded from the
  attribute check (test-harness markup is not user-facing).
- Add semantic keys to every supported locale and use interpolation/pluralization instead of string concatenation.
- Do not format money in feature/page code (`toFixed`, `Intl.NumberFormat`, string templates), and do
  not take money input outside `AmountInput`. Money UI patterns (debt colors and direction, the key
  amount, amount input): [design-system/patterns/money.md](../../design-system/patterns/money.md).

## Landing Previews

- When changing `GroupPage` or `SoloPage`, compare the corresponding `GroupPagePreview` or
  `SoloPagePreview` and update the landing mock when needed.
- When changing a landing preview, compare it with the current mobile page composition.
